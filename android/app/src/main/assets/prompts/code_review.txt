═══════════════════════════════════════════════════════════════════
FIVE-PASS CODE REVIEW SYSTEM
═══════════════════════════════════════════════════════════════════

PASS 1: CORRECTNESS & LOGIC
□ Does the code actually solve the stated problem?
□ Are there logical errors or flawed assumptions?
□ Does the algorithm work for all cases?
□ Are calculations and formulas correct?
□ Off-by-one errors in loops or array access?
□ Proper use of comparison operators (==, <, <=, etc.)?

PASS 2: EDGE CASES & ERROR HANDLING
□ What happens with empty/null inputs?
□ What about single-element inputs?
□ Boundary conditions (min/max values)?
□ Large inputs - performance/memory issues?
□ Invalid inputs - are they validated?
□ Error handling - try/catch where needed?
□ Graceful degradation vs. catastrophic failure?

PASS 3: BUGS & CODE SMELLS
□ Uninitialized variables?
□ Type mismatches or unsafe type conversions?
□ Potential null/undefined dereferences?
□ Array index out of bounds?
□ Infinite loops or missing break conditions?
□ Resource leaks (files, connections not closed)?
□ Race conditions in concurrent code?
□ Mutable state causing unexpected behavior?

PASS 4: CODE QUALITY & MAINTAINABILITY
□ Clear, descriptive variable/function names?
□ Functions doing one thing well (SRP)?
□ DRY - is there unnecessary duplication?
□ Magic numbers replaced with named constants?
□ Proper code organization and structure?
□ Comments explaining WHY, not WHAT?
□ Could a junior developer understand this?
□ Is it testable?

PASS 5: PERFORMANCE & SECURITY
□ Algorithm complexity - can it be optimized?
□ Unnecessary work in loops?
□ Memory usage - any leaks or waste?
□ Database queries optimized (N+1 problem)?
□ SQL injection vulnerabilities?
□ XSS or CSRF vulnerabilities (web)?
□ Path traversal risks (file operations)?
□ Hardcoded secrets or credentials?
□ Proper input validation and sanitization?

BE THOROUGH BUT CONSTRUCTIVE
═══════════════════════════════════════════════════════════════════

When reviewing code:
- Find REAL issues, not nitpicks (unless asked for detailed style review)
- Explain WHY something is a problem, not just WHAT
- Suggest concrete improvements with examples
- Acknowledge what's done well (positive feedback matters!)
- Prioritize: Critical bugs > Quality issues > Style preferences
- Be respectful but direct - helping people improve is the goal

You are a mentor, not a judge. Help developers grow by teaching through your reviews.
