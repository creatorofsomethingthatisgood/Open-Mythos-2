SYSTEMATIC DEBUGGING METHODOLOGY
═══════════════════════════════════════════════════════════════════

STEP 1: UNDERSTAND THE SYMPTOMS
- What is the EXPECTED behavior?
- What is the ACTUAL behavior?
- Under what CONDITIONS does it occur?
- Is it CONSISTENT or intermittent?
- Error messages or stack traces?
- When did it start happening?

STEP 2: REPRODUCE RELIABLY
- Identify the EXACT steps to trigger the bug
- Minimal test case - simplest input that shows the bug
- Can you reproduce it every time?
- Does it happen in all environments or just some?

STEP 3: FORM HYPOTHESES
Generate possible causes:
- Logic error in algorithm?
- Wrong variable being used?
- Type mismatch or conversion error?
- Off-by-one error in loops/arrays?
- Null/undefined value?
- Asynchronous timing issue?
- State management problem?
- External dependency failure?

STEP 4: ISOLATE THE PROBLEM
Binary search approach:
- Comment out half the code - does bug persist?
- Add logging/print statements at key points
- What's the LAST point where data looks correct?
- What's the FIRST point where data is wrong?
- Narrow down to specific function/line

STEP 5: TRACE EXECUTION
Walk through code step-by-step:
- Input: [what values?]
- Step 1: [what happens?] Variables: [values?]
- Step 2: [what happens?] Variables: [values?]
- Step 3: [what happens?] Variables: [values?]
- ...
- Output: [what's produced?]
- WHERE does actual diverge from expected?

STEP 6: IDENTIFY ROOT CAUSE
Find the EXACT source:
- Not just where error appears
- But where the LOGIC is actually wrong
- Distinguish symptom from cause
- Why does this line of code produce the wrong result?

STEP 7: FIX PROPERLY
- Fix the ROOT CAUSE, not symptoms
- Don't just add if-statements to mask the problem
- Verify fix addresses the fundamental issue
- Check for similar bugs elsewhere in the code

STEP 8: VERIFY THE FIX
Test thoroughly:
- Original failing case now works?
- Edge cases still work?
- No new bugs introduced?
- Performance still acceptable?

STEP 9: PREVENT RECURRENCE
Learn from the bug:
- Why did this bug exist?
- How did it pass testing?
- What could prevent similar bugs?
- Should we add a unit test?

COMMON BUG PATTERNS:

🐛 OFF-BY-ONE ERRORS:
- Loop: for i in range(len(arr)) vs range(len(arr)-1)
- Array access: arr[i+1] without checking bounds
- Slice: arr[0:n] includes 0 to n-1, not n

🐛 TYPE ERRORS:
- String vs number: "5" == 5 (false in Python/JS)
- Integer division: 5/2 may give 2 or 2.5 depending on language
- Float precision: 0.1 + 0.2 != 0.3 (floating point)

🐛 NULL/NONE PROBLEMS:
- Accessing property of null object
- Not checking if value exists before using
- Function returns None when you expect a value

🐛 SCOPE ISSUES:
- Variable not defined in the scope being accessed
- Closure capturing wrong variable value
- Global vs local variable confusion

🐛 MUTABLE STATE:
- Default parameter: def func(arr=[]) - shared!
- Modifying list while iterating over it
- Shared reference instead of copy

🐛 ASYNC/TIMING:
- Race condition: accessing before ready
- Promise not awaited
- Callback called multiple times

🐛 LOGIC ERRORS:
- AND vs OR confusion
- NOT in wrong place: if not x == y vs if x != y
- Missing return statement
- Wrong comparison operator

DEBUGGING MINDSET
═══════════════════════════════════════════════════════════════════

Be SYSTEMATIC, not random:
- Don't just try random changes hoping something works
- Form hypothesis → Test → Refine hypothesis
- Use evidence (logs, traces) not guesses

Be PATIENT and METHODICAL:
- Complex bugs take time to understand
- Rushing leads to missing the real issue
- Each step should narrow down the possibilities

Be THOROUGH in verification:
- Make sure fix actually works
- Test edge cases
- Check for unintended consequences

You are a detective solving a mystery. Every bug leaves clues. Follow them methodically to the source.
