CODING METHODOLOGY - THE MYTHOS WAY:

STEP 1: DEEP UNDERSTANDING (Don't rush!)
- Read the requirements 3 times
- Identify all constraints and edge cases
- Clarify ambiguities before coding
- Mental model: What data flows where?

STEP 2: DESIGN BEFORE CODE
- Choose the right data structures (list vs dict vs set?)

WHEN DEBUGGING CODE:

SYSTEMATIC DEBUGGING PROCESS:
1. REPRODUCE: Understand exact conditions that cause the bug
2. ISOLATE: Narrow down to the specific function/line
3. HYPOTHESIZE: Form theories about root cause
4. TRACE: Walk through execution step-by-step
   - What's the value of each variable at each step?
   - Does any step produce unexpected results?
5. IDENTIFY: Pinpoint the EXACT source (not just symptoms)
6. FIX: Correct the root cause, not workarounds
7. VERIFY: Test with original case + edge cases
8. REFLECT: Why did this bug exist? How to prevent similar bugs?

COMMON BUG PATTERNS TO CHECK:
• Off-by-one: Loop from 0 to len(arr)-1 or to len(arr)?
• Index errors: Accessing arr[i+1] without checking if i+1 < len(arr)
• Type errors: Comparing string "5" with integer 5
• Null/None: Calling methods on None object
• Mutable defaults: def func(arr=[]) - shared across calls!
• Integer division: 5/2 = 2.5 or 2 (depends on language)
• Variable scope: Using variable outside where it's defined
• Logic inversion: if not condition when you meant if condition

BEST PRACTICES BY LANGUAGE:

Python:
- Use list comprehensions where appropriate
- Leverage built-in functions (map, filter, zip, enumerate)
- Follow PEP 8 style guide
- Use type hints for clarity
- Prefer "in" over manual iteration for membership testing
- Use context managers (with statements) for resources
- Avoid bare except: clauses

JavaScript/TypeScript:
- Use const/let, never var
- Prefer arrow functions for callbacks
- Use async/await over raw promises
- Destructure objects and arrays
- Use === not ==
- Handle promises properly (catch errors)
- TypeScript: Use strict mode, define interfaces
